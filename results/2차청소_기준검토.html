1 현재 2차 청소 금액 반영 로직 현재 적용 중

월별 정산에서 세대 청소(1차·2차) 금액은 청소일(date) 기준으로 해당 월에 귀속됩니다. 2차 청소의 경우 서명(confirmed=1)이 완료된 세대 수가 해당 층 전체 세대와 일치해야 청구 금액이 발생합니다.

// ── 세대청소 쿼리 (현재)

⚠ 현재 로직의 핵심 제약 청소일(c.date)이 6월이면, 해당 레코드는 6월 정산 쿼리에만 포함됩니다. 7월에 서명이 완료(confirmed=1)되어도 7월 조회 시 해당 레코드가 쿼리에서 제외되어 청구 금액이 반영되지 않습니다.

현재 발생하는 문제 6월 29일에 청소가 완료되고 7월 2일에 서명이 이루어지면, 6월 정산에는 미서명(confirmed=0)이라 금액이 없고, 7월 정산에는 청소일이 6월이라 아예 포함되지 않아 영구적으로 청구 누락이 발생합니다.
개선 후 동작 2차 청소는 서명일(sign_date)이 해당 월이면 그 월에 귀속됩니다. 청소일이 전달이어도 서명이 이번 달에 완료되었다면 이번 달 청구에 포함됩니다.

5 영향 범위 및 주의사항

변경 후 달라지는 것

  • 2차 청소 청구 월 = 서명 완료월로 정확하게 반영
  • 월말 청소 → 익월 서명 케이스 더이상 누락 없음
  • 이전 월 중복 청구 방지 로직(prevCompleteSet)도 서명일 기준으로 일관성 유지

주의사항

  • 기존 데이터 중 sign_date가 NULL인 레코드는 date 기준 유지 (호환 처리됨)
  • 1차 청소는 변경 없음 — date 기준 유지
  • 변경 후 처음 조회 시 기존 정산과 금액 차이 발생 가능 (서명일이 다른 달인 경우)
📋 레거시 데이터 호환 sign_date 컬럼은 2026년 마이그레이션으로 추가되었습니다. 마이그레이션 이전 레코드의 경우 sign_date IS NULL이 될 수 있으며, 이 경우 ELSE c.date로 폴백(fallback) 처리됩니다.

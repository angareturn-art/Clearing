CLEARING · 관리자 운영 매뉴얼

신규 현장(사이트) 추가 가이드

다중 현장 구조를 쓰는 Clearing 시스템에 새 건설 현장을 하나 더 등록하고, 해당 현장에서 시스템을 바로 쓸 수 있도록 기준정보를 세팅하는 절차입니다.

대상: role = admin 백엔드 :5010 · 프론트 :3000 DB: server/construction.db
단계
00 작업 전 백업 01 관리자 토큰 확보 02 현장 등록 API 호출 03 현장 선택 화면 확인 04 동/호수 기준정보 등록 05 작업자·기타 정보 등록 06 최종 점검
00

작업 전 백업 (필수)

Clearing 프로젝트 규칙상 DB에 손을 대는 모든 작업은 물리적 백업을 먼저 수행해야 합니다. 현장 추가도 sites 테이블에 행(row)을 쓰는 작업이므로 예외가 아닙니다.

⛔
백업 없이 진행 금지

server/construction.db 파일을 복사해 server/construction_backup_YYYYMMDD_HHMM.db 형식으로 보관한 뒤 다음 단계로 진행하세요. 과거 백업 누락으로 입력 데이터가 유실된 사례가 있어 예외 없이 적용되는 규칙입니다.

PowerShell 백업 예시
Copy-Item server\construction.db server\construction_backup_20260704_1000.db
01

관리자 토큰 확보

현재 화면에는 "현장 추가" 버튼이 없습니다. POST /api/sites API가 서버에 이미 구현되어 있지만 이를 호출하는 UI가 아직 연결되어 있지 않기 때문에, 관리자 계정으로 로그인한 뒤 브라우저에 저장된 인증 토큰을 이용해 직접 API를 호출해야 합니다.

  1. Clearing 앱(http://localhost:3000)에 admin 권한 계정으로 로그인합니다.
  2. 브라우저 개발자 도구(F12) → Console 탭을 엽니다.
  3. 아래 명령으로 토큰 값을 확인합니다.
localStorage.getItem('ba_token')

따옴표를 제외한 문자열이 JWT 토큰입니다. 이 값을 다음 단계 요청의 Authorization 헤더에 사용합니다.

⚠
admin 이 아니면 403

서버가 req.user.role !== 'admin'인 경우 "관리자만 현장을 추가할 수 있습니다" 오류를 반환합니다. 일반 작업자 계정 토큰으로는 다음 단계가 실패합니다.

02

현장 등록 API 호출

확보한 토큰으로 POST /api/sites를 호출해 새 현장 레코드를 생성합니다. 브라우저 콘솔에서 바로 실행하는 방법이 가장 간단합니다 (토큰을 다시 붙여넣지 않아도 되고, 세션 쿠키/오리진이 이미 일치합니다).

요청 바디 필드
필드설명필수
name현장명 (예: "OO 아파트 신축현장")필수
primary_contractor원청사명선택
subcontractor하청사명 (소속사)선택
address현장 주소선택
start_date착공일 (YYYY-MM-DD)선택
end_date준공 예정일 (YYYY-MM-DD)선택
방법 A — 브라우저 콘솔 (권장)
fetch('/api/sites', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'Authorization': 'Bearer ' + localStorage.getItem('ba_token')
  },
  body: JSON.stringify({
    name: '신규 현장명',
    primary_contractor: '원청사명',
    subcontractor: '하청사명',
    address: '현장 주소',
    start_date: '2026-07-04',
    end_date: ''
  })
}).then(r => r.json()).then(console.log)
방법 B — PowerShell (앱 밖에서 실행할 때)
$token = "여기에_JWT_토큰_붙여넣기"

Invoke-RestMethod -Uri "http://localhost:5010/api/sites" `
  -Method Post -ContentType "application/json" `
  -Headers @{ Authorization = "Bearer $token" } `
  -Body (@{
      name = "신규 현장명"
      primary_contractor = "원청사명"
      subcontractor = "하청사명"
      address = "현장 주소"
      start_date = "2026-07-04"
      end_date = ""
    } | ConvertTo-Json)

정상 처리되면 { "id": 2 } 형태로 새로 생성된 현장의 id가 반환됩니다. 이 번호가 이후 site_id로 시스템 전반에서 사용됩니다.

03

현장 선택 화면 확인

로그아웃 후 재로그인하거나, 사이드바에서 현재 현장을 해제하면 현장 선택 화면이 뜹니다. 방금 만든 현장이 카드로 표시되는지 확인하고 클릭해 진입합니다.

SiteSelector · Select Project Site
기본 현장
원청: 원청사 미지정
하청: 하청사 미지정
NEW
신규 현장명
원청: 원청사명
하청: 하청사명

목록에 보이지 않으면 sites.status 값이 'active'인지 확인하세요 — 이 화면은 WHERE status = 'active' 조건으로만 현장을 불러옵니다.

04

동/호수 기준정보 등록

새 현장은 site_id가 다르기 때문에 건물(동)·세대(호) 데이터를 처음부터 새로 입력해야 합니다. 기존 현장의 기준정보는 자동으로 복사되지 않습니다.

기준정보 (Settings)
현장 정보 동/호수 관리 주요 메뉴 사용자 관리

사이드바 관리 → 기준정보 진입 → 동/호수 관리 탭에서 동(건물), 층수, 기준층(박리제/청소), 라인 구성을 입력합니다.

이 단계에서 입력할 것

  • 동(건물) 이름, 지하층 수, 주소
  • 박리제(기름칠) 기준층, 청소 기준층
  • 동별 호수(라인) 구성 및 층수
✓
자동 격리

등록한 데이터는 서버가 요청 헤더의 X-Site-Id를 읽어 자동으로 현재 현장의 site_id로 저장하므로, 별도 설정 없이도 다른 현장 데이터와 섞이지 않습니다.

05

작업자 · 기타 정보 등록

작업자(workers), 단가 이력(worker_wage_history), 비상연락망 등도 모두 site_id로 구분되는 테이블입니다. 새 현장에서 바로 기록을 입력하려면 아래도 함께 채워야 합니다.

현장별로 다시 입력해야 하는 항목
메뉴내용
작업자작업자 기준정보 등록 (역할/팀/단가)
비상연락망현장 관계자 비상 연락처
기준정보 > 주요 메뉴현장에서 노출할 탭 구성 커스터마이즈 (선택)

사용자 계정(users)은 현장별로 분리되지 않으므로, 기존 로그인 계정으로 바로 새 현장을 조회·입력할 수 있습니다. 계정을 새로 만들 필요는 없습니다.

06

최종 점검

  • 현장 선택 화면에 새 현장 카드가 보인다
  • 대시보드/배치도에 등록한 동·호수가 정상 표시된다
  • 다른 현장으로 전환했을 때 데이터가 서로 섞이지 않는다
  • 백업 파일이 server/에 생성되어 있다

이상이 없으면 등록이 완료된 것입니다. 이후 현장 정보(현장명·원청·하청) 수정은 기준정보 → 현장 정보 탭에서 관리자 권한으로 언제든 변경할 수 있습니다.

참고 · 신규 현장 등록은 현재 API로만 가능하며(관리자 전용 UI 버튼 미구현), 절차의 핵심은 sites 테이블에 행을 만드는 02단계와 그 site_id로 기준정보를 새로 채우는 04–05단계입니다.

# 기록 화면 동별 조회 필터 추가 계획

## 목표
기록(Records) 화면에 동(건물)별 조회 필터를 추가하여, 동별로 날짜 내림차순으로 기록을 조회할 수 있도록 한다.

## 현황 분석
- **백엔드** (`server/index.js` L641~652): `/api/records/:type` GET API는 이미 `buildingId` 쿼리 파라미터를 지원함 ✅
  - `date` 파라미터가 있으면 날짜 필터 적용
  - `buildingId` 파라미터가 있으면 건물 필터 적용
  - 현재 정렬: `ORDER BY r.created_at DESC` (고정)
- **프론트엔드** (`src/App.jsx`): 
  - `filterBuilding` 상태는 이미 존재하지만 UI에 버튼이 없음
  - `filterDate`와 `filterBuilding`을 **동시에** URL 파라미터로 전송 중 → 동별 조회 시 날짜 필터가 같이 걸려 문제 발생

## 변경 범위

### 수정 파일 1: `src/App.jsx` (Records 탭 UI 부분만)

#### 추가할 상태
```js
// 조회 모드: 'date' | 'building'
const [filterMode, setFilterMode] = useState('date');
```

#### UI 변경 (기록 탭 필터 영역)
```
┌────────────────────────────────────────────────────────┐
│  [청소] [박리제칠] [갱폼인양]     [일자별] [동별]        │
├────────────────────────────────────────────────────────┤
│  일자별 모드: 날짜 입력 필드  +  [기록 추가]             │
│  동별 모드:  [1동][2동][3동]...[9동] 버튼   [기록 추가]  │
└────────────────────────────────────────────────────────┘
```

#### fetchRecords 로직 변경
- `filterMode === 'date'` → `?date=2026-05-18` (날짜만 전달, 현재 일자 해당 데이터)
- `filterMode === 'building'` → `?buildingId=3` (건물ID만 전달, 날짜 미전달 → 해당 동 전체를 날짜 내림차순으로 반환)

#### 정렬 처리
- 동별 모드 시 백엔드는 이미 `ORDER BY r.created_at DESC` 이므로 날짜 내림차순 자동 적용 ✅
- 단, 날짜가 보이도록 테이블에 **날짜 컬럼 추가** 필요 (동별 모드에서는 날짜 정보가 중요)

### 수정 파일 2: `server/index.js` (최소 변경)
- **별도 변경 불필요**: 이미 `buildingId` 단독 조회가 가능하고 정렬도 내림차순이므로 백엔드 변경 없음 ✅

## 구현 순서
1. `App.jsx`에 `filterMode` 상태 추가
2. `fetchRecords` 함수 수정 (모드별 파라미터 분기)
3. 기록 탭 UI에 **[일자별] [동별]** 토글 버튼 추가
4. 동별 모드일 때 건물 버튼 row 표시
5. 동별 모드일 때 테이블에 날짜 컬럼 추가
